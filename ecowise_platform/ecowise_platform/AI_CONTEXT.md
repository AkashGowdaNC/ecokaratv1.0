# EcoKarat Platform - Project Context

This document is designed to give any AI or developer a complete, high-level understanding of the EcoKarat platform, its architecture, and its purpose.

## 1. Core Concept & Domain
**EcoKarat** is a B2B Software-as-a-Service (SaaS) platform built to manage and monetize post-event plastic waste in Karnataka, India. 
It connects three main "nodes" in the recycling ecosystem:
*   **Marriage Halls (Generators):** Produce large amounts of plastic waste (water bottles, plates) after events. They use the platform to schedule pickups and earn money.
*   **Recycling Centres (Processors):** Accept the waste, process it, and issue verifiable environmental impact/EPR (Extended Producer Responsibility) certificates.
*   **Manufacturers (Consumers):** Buy processed PET flakes from recyclers (future feature).

## 2. Technology Stack
*   **Backend:** Node.js with Express.
*   **Database:** MongoDB (via Mongoose ORM).
*   **Frontend:** Single Page Application (SPA) using HTML5, Vanilla JavaScript (`app.js`), and Tailwind CSS via CDN.
*   **Authentication:** JWT (JSON Web Tokens) handled in the backend and stored in `localStorage` on the frontend.

## 3. The Design System: "Emerald Zenith"
The frontend utilizes a custom UI/UX design system generated by Google's Stitch AI, titled **Emerald Zenith**.
*   **Aesthetic:** "The Living Laboratory" - A premium, dark-mode-first, SaaS dashboard look.
*   **Colors:** Deep obsidian backgrounds (`#0a0f0d`, `#101410`) with vibrant neon emerald accents (`#10b981`, `#4edea3`).
*   **Styling:** Heavy use of "Glassmorphism" (`backdrop-blur`, semi-transparent panels), kinetic depth (3D hover effects using `perspective`), and minimal "ghost" inputs without hard borders.
*   **Typography:** *Space Grotesk* for technical, high-impact headlines and *Manrope* for highly readable body text.

## 4. Frontend Architecture (`public/index.html` & `public/js/app.js`)
The frontend operates as a single file (`index.html`) containing multiple hidden "views" (Auth view, Dashboard view). `app.js` handles the logic to toggle these views.
*   **Dynamic Sidebar:** The navigation menu changes based on the user's role (`admin`, `hall`, `recycler`).
*   **API Integration:** The frontend uses standard `fetch()` calls to interact with the backend (e.g., `POST /api/login`, `GET /api/pickups`).

## 5. Backend Architecture (`server.js`)
The Node.js server handles routing, database connections, and business logic.
*   **User Roles:** Hardcoded/managed in the database (e.g., `demo@ecowise.org` -> Admin).
*   **Pickups Model:** Stores data about waste collection events (Event Name, Date, Estimated kg, Status).
*   **Status Flow:** Pickups move through statuses: `scheduled` -> `assigned` -> `completed`.
